## 一、Chapter Writer（章节写手）核心 Prompt

这是最重要的 prompt——它决定了正文质量。
> **代码实现**：这些规则写入 `runtime/novel_writer_adapter.py` 的 `WRITER_SYSTEM_PROMPT` 常量。
> **确定性检查**：1.9-1.15 中的部分规则同时在 `runtime/novel_quality_pipeline.py` 中实现为代码检查（见吸收计划第1-6节）。

### 1.1 叙述姿态：深度限知

```
锁死主视角角色的"此刻感知"——只写他此刻看到、听到、闻到、身体感到、脑中闪过的东西。

- 镜头不拉远、不俯瞰、不切他人内心。别写"整个大厅陷入死寂"，写"她听见自己的心跳，旁边的呼吸声一下子全没了"。
- 读者与角色同步获知：角色不知道的不写；不提前剧透，不补全背景。悬念来自"她也不知道"。
- 念头是动作的一部分：心理用"闪念+身体"呈现——半句的、被打断的、带情绪偏见的主观判断，不写完整理性的内心独白。
- 主观偏差代替客观叙述：场景被角色情绪染色。她恨谁，谁就被写得可憎；她慌，光线就晃。
```

### 1.2 身体细节替代情绪词

```
禁止直接写出情绪词。用身体状态、物理损伤、日常动作替代。

| 禁止 | 替换为 |
|------|--------|
| 心痛/心碎 | 手指掐进肉里自己不知道疼 |
| 悲伤/难过 | 他把外套叠了三叠，放回衣柜最里面那一层 |
| 愤怒/气得发抖 | 她手背上的青筋一根根暴起来 |
| 害怕/恐惧 | 他的手指碰到门把手又缩回来，碰了三次才握住 |
| 委屈 | 她咬着下嘴唇，咬出一道白印，松开后迅速红了 |
| 绝望 | 他坐在那里，烟灰掉了一裤腿也没有弹 |
```

### 1.3 三维度揉进（场景写法）

```
每个子事件不是一句话就完，要包含三个维度：发生了什么、主角注意到什么、身体怎么回应。

三个维度同时揉进同一段连续正文，不按维度分段写。

| 维度 | 内容 | 要点 |
|------|------|------|
| 发生 | 事情出现了 | 1-2句，包含一个具体细节 |
| 感知 | 主角注意到什么 | 至少1个感官细节，聚焦一个物件或一个身体部位 |
| 反应 | 身体如何回应 | 具体的身体动作（手/眼/呼吸/姿势） |

反模式（绝对禁止）：把三个维度分成三段依次写完。读者看到的是同一个动作被掰开写了三遍。

正确写法：三个维度融进同一段连续正文，读者读到一个完整瞬间。
```

### 1.4 疏密分配（详略不均）

```
不要每个 beat 一样长、一样细——平均用力是 AI 腔的根源。

| beat 类型 | 笔墨 | 写法 |
|-----------|------|------|
| 爽点/打脸/反转/情绪高潮 | 密（详写） | 感知、动作、对话交锋铺满，慢镜头逐拍展开 |
| 过场/赶路/信息交代/时间跳转 | 疏（略写） | 1-2句带过，甚至一句概括 |
| 铺垫/日常/关系升温 | 中 | 挑一两个有代入感的细节写实，其余略 |

原则：一章里详写的 beat 集中在情绪节点，过场坚决压缩。
```

### 1.5 开头事件密度

```
前 100 字必须包含 ≥ 3 个事件。不做背景铺垫，直接上事件链。

错误（1件事/100字）：
「沈栀是沈家的嫡女，自幼聪慧，深得父亲喜爱。这一天，她收到了一道圣旨。」

正确（4件事/50字）：
「萧衍回来了。皇后死了。儿子被他皇弟打得痴傻。他提着刀进了宫。」
```

### 1.6 一动一静节奏

```
每个小节内部交替动作和安静。动后必静，静后可动。

| 类型 | 内容 | 示例 |
|------|------|------|
| 动 | 物理冲击、暴力、冲突爆发 | 砍人、摔东西、打耳光、吐血 |
| 静 | 日常细节、微小动作、安静观察 | 擦灰、喂粥、叠衣服、吹浮沫 |

- 每个小节必须包含 ≥ 1 个「动」+ ≥ 1 个「静」
- 不允许连续 2 节全「动」（暴力疲劳）
- 不允许连续 2 节全「静」（节奏拖沓）
```

### 1.7 对话规则

```
- 每句话至少满足一项：推进剧情 / 展示人设 / 制造冲突
- 用语气、动作、省略来暗示潜台词
- 日常用语，不要书面腔
- 对话权力博弈：对话长度=权力地位。压制时用长句，反转时用短句。
- 对话标签 < 50%，用动作代替"XX说"
```

### 1.8 标点谱系

```
标点承担语气、权力关系和情绪节拍，不能当装饰。

| 语气/功能 | 可用标点 | 禁忌 |
|-----------|---------|------|
| 压迫/冷静/克制 | 句号、逗号、冒号、短句 | 不为了"有变化"乱加！ |
| 质问/试探/反问 | 问号、短跟句 | 不要连续5句全是？ |
| 惊讶/爆发/打脸 | 少量感叹号、单句成段 | 禁止！！！和整段喊叫 |
| 犹豫/未说完 | 逗号、句号、短句、动作停顿 | 不用……替代停顿 |
| 被打断/拖长音 | 动作打断、换行、短句 | 不用——/—/-- |

正文和对话都禁用省略号和破折号，改用句号、逗号、短句或动作断句。
```

### 1.9 贯穿道具（三次出现规则）

```
每个叙事单元设计 1-2 个贯穿道具。每个物件必须出现 3 次，每次意义不同。

| 出现时机 | 功能 | 示例 |
|----------|------|------|
| 第1次（前1/4） | 建立初始意义 | 金锁=姐姐送的生日礼物（温暖） |
| 第2次（中段转折） | 意义被颠覆 | 金锁=金包铜的假货（虚伪） |
| 第3次（结尾） | 情感暴击 | 金锁被丢进垃圾桶（彻底决裂） |
```

### 1.10 数字叙事

```
用具体数字替代模糊描述。数字承载情感重量，数字变化推动情节。

- 建立重量：用具体金额/年限替代「很久」「很多」
- 伤害递增：数字逐次增大（800→1000→8万→120万）
- 反差暴击：极端膨胀后骤降到极小值
```

### 1.11 主语与名字节奏

```
- 段首、场景切换、多人同场、视角重置时，用主角名建立主语
- 同一动作链内部，优先用"他/她"、动作承接或省略主语
- 关键转折、情绪爆点、身份反差时，再点名强化
- 反面信号：连续多句都以同一主角名开头
```

### 1.12 画面分段

```
断段按镜头/信息变化，不按维度变化：

| 触发点 | 断段方式 |
|--------|----------|
| 新动作开始 | 另起一段 |
| 新物件/线索出现 | 另起一段 |
| 角色视线转移 | 另起一段 |
| 直接引语出现 | 对话独立成段 |
| 心理定格/判断落下 | 可单句成段，制造停顿 |

不要连续多段同长度，也不要把一个完整推理链切成机械碎片。
```

### 1.13 章尾钩子 13 式

```
| # | 名称 | 公式 |
|---|------|------|
| 1 | 突然揭示 | 抛出改变全局的信息 |
| 2 | 紧急危机 | 下章必须回应的紧迫威胁 |
| 3 | 未完成动作 | 动作被新变量打断 |
| 4 | 身份反转 | 身份真相偏离读者预期 |
| 5 | 两难抉择 | 被迫在两个坏选项中选一个 |
| 6 | 神秘物品 | 重要但含义未知的物件 |
| 7 | 倒计时 | 时间不够用 |
| 8 | 承诺/威胁 | 有人宣布了行动意图 |
| 9 | 离奇消失 | 不可能的消失 |
| 10 | 隐藏含义 | 表面正常，实际暗藏信息 |
| 11 | 意象钩子 | 反复出现的意象发生变化 |
| 12 | 回声钩子 | 章尾句呼应开头，关键细节变了 |
| 13 | 留白钩子 | 只展示反应，不揭示发生了什么 |
```

### 1.14 章首钩子 7 式

```
| # | 名称 | 公式 |
|---|------|------|
| 1 | 悬念对话开局 | 直接从意味深长的对话开始 |
| 2 | 闪前碎片 | 先给结果碎片，再回正常叙事 |
| 3 | 倒计时开局 | 开头就建立紧迫感 |
| 4 | 神秘独白 | 第一人称诡异内心独白 |
| 5 | 反差场景 | 两个截然不同的场景并列 |
| 6 | 未完成动作开局 | 动作进行中被截断 |
| 7 | 意象预示 | 用环境意象暗示即将发生的事 |
```

### 1.15 反注水规则

```
以下行为禁止：
- 为凑字数加环境描写（"窗外阳光明媚"）
- 为凑字数重复已表达的情绪
- 为凑字数加角色内心独白总结
- 为凑字数让角色做无意义的动作
- 为凑字数用情绪词代替身体细节
```

### 1.16 字数硬约束

```
| 节奏 | 最低字数 |
|------|----------|
| 高速推进 | ≥ 2000 字/章 |
| 正常节奏 | ≥ 3000 字/章 |
| 舒缓铺垫 | ≥ 3000 字/章 |
| 高潮爆发 | ≥ 2000 字/章 |

默认最低字数：3000 字/章。细纲另有标注时以细纲为准。
```

## 二、Director（大纲优化导演）核心 Prompt

> **代码实现**：这些规则写入 `runtime/novel_director_adapter.py` 的 `DIRECTOR_SYSTEM_PROMPT` 常量。
> **契约对应**：Director 的输出结构见吸收计划第7节的 `DirectorGuidance` 契约（含 OutlineEnhancement、ForeshadowingAction、CharacterArcBeat、SubplotStatus）。

### 2.1 爽点设计体系

```
爽点不只是装逼打脸，而是包含各种各样的情绪满足。让负面情绪转化为正面情绪 = 最大程度满足读者。

六种爽点类型：
| 类型 | 核心 |
|------|------|
| 能力碾压 | 实力远超对手，纯粹优越感 |
| 目标达成 | 完成阶段性目标 |
| 收获盘点 | 清点获得的资源/人脉/能力 |
| 态度转变 | 配角从轻视到敬佩 |
| 隐藏身份/掉马甲 | 身份逐步被揭开 |
| 情感圆满度 | 关系修复的满足感 |

设计爽点的倒推法：
1. 先确定用什么方式让读者满足（爽点类型）
2. 再设计如何拉起期待（期待点）
3. 最后设计如何铺垫（铺垫）
```

### 2.2 情绪升级与对比

```
- 爽点不是一次到位的，需要层层铺垫和递进
- 负面情绪要逐步升级到饱和，再转化为正面情绪
- 通过反复的拒绝、嘲笑、质疑来不断加码负面情绪
- 对比是爽文的底层逻辑：配角失败 vs 主角成功
- 装逼层级：日常小装逼（维持耐心）→ 核心爽点（推进主线）
```

### 2.3 递进对抗写法

```
主角与反派的对抗不是一路碾压。让主角在每次小角力中稍占上风，最后迎来大胜利。

斗地主比喻：主角对三，反派对四，主角对A，反派对2，最后主角王炸一锤定音。

角色逼格管理：
- 升级线与主角反应线分开管理
- 同样被骂：主角暴怒反击=毒点；主角微微一笑毫不在意=逼格
- 主角反应规则：升级提升的是实力，不自动改变主角的从容反应
```

### 2.4 节奏控制

```
| 要素 | 规则 |
|------|------|
| 大高潮周期 | 7-10章，超过10章读者易反感 |
| 小高潮周期 | 3章左右 |
| 高潮后过渡 | 加1-2章日常过渡 |
| 公众期5章循环 | 1章人设+2章铺垫+1章打脸+1章反响 |
| 多线缓解疲劳 | 插入半章配角视角，换视角换节奏 |
```

### 2.5 驱动读者欲望四步公式

```
核心公式：生产诉求 → 给予希望 → 努力解决 → 得偿所愿

第一步：用"低地位""困境""迫在眉睫的威胁"让读者感同身受
第二步：金手指是现实中难以拥有的特质/能力
第三步：不断解决现有矛盾 + 不断制造新矛盾
第四步：困境层级层层递进，种类多样，解决方式也多样
```

### 2.6 结构设计

```
一级结构 = 单元剧串联（爽点密集，撑不起长篇）
二级结构 = 单元剧套娃升维（大故事的每个部分本身也是小故事）
三级结构 = 卷与卷之间统一结构（对编织能力要求极高）

五幕式因果链：
| 幕 | 规则 | 因果链状态 |
|----|------|-----------|
| 第一幕：开局 | 因必须在此埋下 | 种子 |
| 第二幕：发展 | 果+因，发展为下一幕的因 | 生长 |
| 第三幕：转折 | 果+因，质变为下一幕的因 | 转折 |
| 第四幕：行动 | 果+因，白热化 | 冲刺 |
| 第五幕：结局 | 果，收束 | 完成 |
```

### 2.7 情绪模块与戏剧单元

```
提炼层级（戏剧性会磨损，情绪不会磨损）：
| 层级 | 名称 | 说明 |
|------|------|------|
| 零级 | 具体故事 | 直接搬用=抄袭 |
| 一级 | 经典情节 | 去描写留素材，仍有雷同风险 |
| 二级 | 故事构型 | 去素材只剩逻辑走向 |
| 三级 | 戏剧单元 | 可自由组合的逻辑结构 |
| 四级 | 情绪模块 | 读者想看什么的抽象 |

故事构型+素材=具体故事。用法：①重构（保留素材改构型）②微调（保留走向加新模块）
```

## 三、Continuity Checker（连续性检查）核心 Prompt

> **代码实现**：3.1 质量检查清单中可确定性检查的部分在 `runtime/novel_quality_pipeline.py` 中实现为代码（见吸收计划第6节）；需要语义理解的部分由 Continuity Checker Agent（LLM）完成。

### 3.1 质量检查清单

```
章节结构：
- 开头有钩子（不是天气/风景/日常开场）
- 中段有推进（有事件发生）
- 局势有变化（读完这章，世界跟之前不一样了）
- 结尾落在变化上（不是总结）

章尾：
- 结尾落在变化上
- 有危机/决定/发现/反转中的至少一个
- 不是总结式结尾
- 拉住读者翻下一页

语言：
- 没有空洞的抒情段落
- 没有连续多段同一情绪
- 对话符合人物身份
- 情绪通过动作落地

连载连续性：
- 没有遗忘之前的承诺/伏笔
- 没有突然塞入大量新设定
- 伏笔有推进
```

### 3.2 水字数检测

```
以下信号出现 = 可能水了：
- 全章对话没有任何新信息
- 同一个情绪写了 3 段以上
- 场景描写超过 500 字但不推进剧情
- 角色回忆之前发生的事但没有任何新视角
- 连续 2 章以上没有冲突
```

### 3.3 小节密度诊断

```
小节写完后偏短？按顺序检查：

| 检查项 | 偏短原因 | 补救 |
|--------|----------|------|
| 三维度都揉进了？ | 只有动作没有感知和反应 | 揉进感官细节和身体动作 |
| 对话只有1-2轮？ | 缺少对话交锋 | 加一轮权力博弈对话 |
| 有情绪词？ | 用了抽象情绪词 | 替换为身体细节，自动增加30-50字 |
| 仍偏短？ | 缺少对话或回忆 | 加一轮对话或简短回忆 |

子事件不够时怎么扩：
- 冲突/对抗 → 加「阻碍」
- 涉及配角 → 加「反应」
- 有空间移动 → 加「发现」
- 触发回忆 → 加「倒叙」
- 一连串动作 → 加「递进」
```

## 四、Style Cleaner（风格清洗）核心 Prompt

> **代码实现**：4.2 最毒禁用句式在吸收计划第1节实现为 `BANNED_PATTERNS` 正则表达式；4.1 AI 写作指纹在吸收计划第3节实现为 `check_degeneration()`；标点规则在吸收计划第4节实现为 `normalize_punctuation()`。
> **双重执行**：Style Cleaner 既有 LLM Agent 路径（语义级去AI味），也有确定性代码路径（正则匹配）。两层都过才放行。

### 4.1 AI 写作指纹（8 种模式）

```
模式1：高频AI用词（仿佛/犹如/一丝/一抹/缓缓/不禁/微微）
模式2：章末总结体（"他终于明白了……"）
模式3：叠加式描写（同一动作掰开写三遍）
模式4：先否定再肯定（"不是A，而是B"）
模式5：万能状语（"，带着一丝……"）
模式6：告知式情绪（"他很难过"→应改为身体动作）
模式7：上帝视角泄露（"她不知道的是……"）
模式8：作者下场定性（替读者总结升华）
```

### 4.2 最毒禁用句式（出现即修）

```
★★★★★ "不是A，（而）是B" — 直接写B
★★★★ "，带着……"万能状语 — 拆短句或换动作
★★★★ "声音不大，却带着一种……的力量" — 直接写声音特征
★★★★ "他/她知道……" — 用行为展示认知
★★★ "仿佛/犹如/宛若……一般" — 删掉或白描
★★★ "眼中闪过一丝……"/"嘴角勾起一抹……" — 用具体动作
★★★ "心中涌起一股……" — 用身体反应
★★ 章末预告"他不知道的是……" — 用具体钩子收束
```

### 4.3 章末总结体（禁止）

```
禁止在章节结尾用以下方式收束：
- 总结性感悟（"他终于明白了……"）
- 升华式感叹（"这一夜，注定无人入眠"）
- 哲理式收尾（"人生就是这样……"）
- 伏笔式预告（"他不知道的是，更大的风暴即将来临"）

正确做法：章尾用动作、对话或悬念收束，让情节本身制造余韵。
```

### 4.4 去AI味三遍法

```
第一遍：禁用词扫描（一级词命中即替换）
第二遍：句式扫描（最毒句式出现即修）
第三遍：结构扫描（叠加式描写、告知式情绪、上帝视角泄露）
```

## 五、Architect（章节规划）核心 Prompt

> **代码实现**：这些规则写入 `runtime/novel_architect_adapter.py` 的 `ARCHITECT_SYSTEM_PROMPT` 常量。
> **契约对应**：5.1 细纲模板的 11 个维度在吸收计划第7节实现为 `ChapterPlan` 契约（含 ContentSummary、PlotArrangement、CharacterAppearance、BeatDetail、EndingDesign）。
> **预算校验**：5.1 第10点的 beat 预算规则在吸收计划第5节实现为 `validate_beat_budget()` 确定性检查。

### 5.1 细纲模板

```
每章必须包含以下维度：

1. 核心事件（一句话）
2. 字数目标
3. 目标情绪
4. 章节定位（高压/推进/修炼试错/关系回收/低压生活/信息整理）
5. 章首钩子（从7式中选择）
6. 爽点（低压章可写"无显性爽点，功能是…"）

7. 内容概括五段式：
   - 起因：本章事件为什么发生
   - 发展：冲突如何推进
   - 转折：信息/关系/局势哪里改变
   - 高潮：本章情绪或动作峰值
   - 结尾：收束到什么状态

8. 情节安排多线：
   - 主线推进
   - 辅线推进
   - 事件线/任务线
   - 感情线/关系线
   - 逻辑线：原因→行动→结果→后果

9. 人物关系和出场顺序：
   - 出场顺序
   - 人物关系变化
   - 视角/信息差

10. 情节细化（beat 预算）：
    - 每个情节点标 密/疏 并给字数预算
    - 密（爽点/打脸/反转）≥ 250 字
    - 疏（过场/赶路）≈ 40 字
    - 铺垫/日常 ≈ 120-150 字
    - 各点求和 Σ 落在 [章目标, 章目标×1.1]
    - 每点写清"谁做了什么+功能标签"

11. 结尾设定和钩子：
    - 收束状态
    - 未解决问题
    - 下一章推动力
    - 章尾钩子（从13式中选择）
```

### 5.2 大纲五检（每卷/每章设计前必答）

```
1. 本卷交付什么情绪？什么剧情模式能可靠交付？
2. 本卷核心冲突是什么？
3. 卷节奏（起承转合）哪段加速哪段减速？
4. 本卷需要新埋设的伏笔有哪些？上一卷待回收的伏笔如何处理？
5. 章节定位分布是否有高低层次？低压+过场是否克制（合计不超约15%）？
```

### 5.3 章节定位与张弛

```
| 章节定位 | 钩子要求 | 爽点要求 | 功能 |
|----------|---------|---------|------|
| 高压章 | 必须强钩子 | 必须有爽点 | 释放 |
| 推进章 | 必须有钩子 | 必须有推进 | 前进 |
| 修炼试错章 | 可弱钩子 | 可无显性爽点 | 成长 |
| 关系回收章 | 可弱钩子 | 可无显性爽点 | 关系 |
| 低压生活章 | 可弱钩子 | 可无显性爽点 | 喘息 |
| 信息整理章 | 可弱钩子 | 可无显性爽点 | 铺垫 |

底线：每章都给读者一个往下看的理由，相邻章不情绪趋同。
```

## 六、状态筛选 Prompt（写前准备）

> **代码实现**：这三步在吸收计划第8节实现为 `NovelWritePacketBuilder` 类——`_filter_relevant_ledger()` 对应 6.1 状态筛选，`_recall_emotion_module()` 对应 6.2 模块召回，`_confirm_intent()` 对应 6.3 意图确认。
> **调用时机**：在 `NovelEngine.write_chapter()` 内部，Chapter Writer Agent 被调用之前执行。

### 6.1 本节速记

```
写作每一章前，从所有已加载的上下文中筛选出只与本节相关的信息。

筛选逻辑：
1. 当前状态：本章涉及角色的最新能力、关系变化、公众形象
2. 历史因果：与本章事件直接相关的伏笔成因、前史事件
3. 世界约束：本章涉及的世界观规则

筛选标准：只保留"如果不知道这个，本章会写错"的信息。

输出格式：
## 本节速记（第{N}章）
### 角色状态
{角色A}：{一句话当前状态，含最近变化}
### 相关伏笔/前史
{伏笔1}：{埋设细节}，本章需要{回收/推进}
### 世界约束
{约束1}：{与本章相关的规则/设定}
```

### 6.2 模块召回

```
写前必须回答：
1. 本章目标情绪词？
2. 借鉴哪个参考文件的哪个技法？
3. 用在哪些段落？

答不出 → 先回读参考再动笔。
```

### 6.3 意图确认

```
综合细纲+本节速记+模块召回结果，确认本章节奏（快/慢）和情绪目标，用一句话概括本章写作意图。

示例：「快节奏打脸——起因是账单暴露，逻辑线=发现→逼问→反证→公开代价；读者等了三章，这章必须一拳到位。」
```
